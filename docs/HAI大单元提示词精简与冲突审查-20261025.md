# HAI 大单元提示词：去重、冲突与参考资料审查

本次检查对象是大单元四步新建流程中的实际模型请求，包含模式推荐、整体设计和逐课详案。主 Skill 与模板保留全文；课程内容、课标依据、教师已确认方案和前课承接内容不因“出现过”而直接删除。模型每次调用独立，跨请求重复携带依据与同一请求内重复不是一回事。

## 最新选择：只留模式 Reference，缩短逐课请求

教师明确指定后，当前本地运行包的非模板 Reference 只保留 `mode-selection.md`。`input-and-evidence.md`、`quality-criteria.md`、`design-basis.md` 不再包含于新版运行源包；13份模板仍全部保留原文，按模式选用。主 Skill 不裁剪教学内容，仅调整两处已删除 Reference 的链接说明。

逐课请求现在拼接为：

- system：完整主 Skill＋保留的教材事实边界＋本次单课输出协议。
- user：基础备课信息（保留需求与学情，不含教材／课标数据）＋可选上传教学材料＋对应单课模板＋已确认整体设计＋本次课时清单项。

不再另带前一课教案、教材课标正文／结构化来源内容、模式选择对象、历史修改意见和当前阶段反馈。模式已用于后台模板选择，整体设计中原有的模式和教材依据也保留，不额外改写确认稿。

同一真实输入重建后：模式推荐30228→22560字符；整体设计30823→22961字符；第二课57934→23701字符（减少59.1%），该课估算输入42350→17313 tokens。数值来自本地拼接回放，未实际调用模型，不代表生成质量已有新验收。

每次不必带完整 Skill，但必须带当前独立调用所需的行为依据。下一步若按阶段裁剪，可保留共同角色、事实边界、表达和关键质量标准；模式推荐加选型要求，整体设计加四项分析，单课加课堂可用性要求。直接不带 Skill 且不提供替代规则，可能使模型只按模板填栏目，丢失不虚构学情、个人学习证据、具体教师支持和不强套模式等判断。本轮仍加载全文，没有把问题讨论当作删除授权。

以下为第一轮检查记录；其中关于继续保留其他 Reference 的建议，已被上述教师选择覆盖。

## 二、提示词冲突清单

| 冲突或不匹配 | 两边原来分别说什么 | 本轮处理或待决定之处 |
| --- | --- | --- |
| 阶段输出格式互相打架 | 基础 system 一律要求完整整体设计 JSON；模式阶段要求候选 options；课时阶段要求单课 Markdown、不要JSON | 本地已统一为每阶段一份协议，移除新版大单元基础层的整体JSON指令 |
| Reference 状态表述失实 | 基础 system 说“当前专属 Skill 没有可加载的学科 Reference”；执行器随后追加对应参考资料和模板 | 本地已删除这句内部状态提示，实际资料仍正常追加 |
| 模板数量表述含混 | 共用提示说“所有学科、学段使用同一工作流与模板”；主 Skill 实际按六种模式使用六组模板 | 尚保留该既有规则，建议后续改成“所有学科共用四步工作流，按已选模式使用对应模板”，而非误解为全学科只用一种模板 |
| 自动连续完成的授权无法落实到界面 | 主 Skill 允许教师明确授权后连续完成；程序固定两次确认 | 产品能力差异，未擅自改变确认机制。若保留固定两次确认，需要在网页运行说明中明确 |
| “只要整体设计”没有完整产品出口 | 主 Skill 允许在第三步结束交付；程序最终正式版本按1＋N文件齐套保存 | 产品能力差异，未删掉 Skill 这一合理用法，也未擅自增加结算／交付分支 |
| 自行读文件、查库的能力假设不成立 | 主 Skill 中有“读取 references、outputs 案例”的描述，资料说明还谈扫描件、调用工具；当前模型请求只有 system 与 user，没有查库／文件工具 | 后台实际加载的内容才可使用；input-and-evidence 已停默认注入。主 Skill 中未打包的 outputs 链接仍是待处理的环境适配点 |

“逐课调用”与 Skill 的“连续完成全部课时”是执行粒度差异，并非必须删除的教学要求：执行器连续调度，每次只生成一课，最后交付全套。对应阶段协议仍须保留，避免模型一次性输出全套。

同理，课标缺失时留空／说明缺口与“依据真实材料”并不矛盾；它们是对缺失情形的处理，不应为了短而删掉事实边界。

## 四、用真实输入重建请求后的长度变化

采用已保存任务的教材、课标、需求、已确认整体方案和首课正文，分别重建模式推荐、首次整体设计、第二课时请求。无新增模型调用；数值是拼接后的字符数和本项目算法估算 tokens，不是供应商返回的真实消耗，也不代表新稿教学质量已验收。

| 请求 | 原字符数 | 去重后字符数 | 减少 | 原估算tokens | 去重后估算tokens |
| --- | ---: | ---: | ---: | ---: | ---: |
| 推荐模式 | 30,228 | 22,637 | 25.1% | 21,763 | 15,705 |
| 整体设计 | 30,823 | 24,627 | 20.1% | 22,157 | 17,185 |
| 第2课时 | 57,934 | 51,552 | 11.0% | 42,350 | 37,248 |

逐课请求仍长，主要因为整组教材／课标、完整整体方案及前课详案同时存在。它们有内容交叠，但不是可以机械删除的同文副本。若进一步压缩，应分别评估本课需要哪些教材、哪些整体设计约束及哪些前课承接信息，不能把依据直接删空。

第二课去重后估算输入37,248加当前输出预算16,384，仍达53,632，超过5万门槛。现有阶段预留采用原预留与已知单次调用最大值，并非每次最终组装后精确检查；本轮没有改变长度上限或计费机制，不能把“已去重”当作“所有长任务都已适配”。
