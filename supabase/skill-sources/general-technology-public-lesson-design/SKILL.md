# 通用技术公开课设计

把技术课设计成“面对真实需要，在约束中作出有证据的技术决策”，而不是做出一个漂亮作品、照教师步骤装配，或背诵结构/流程/系统术语。公开课必须让观课者看见学生如何界定需求、表达方案、试验或分析、解释失败并依据标准优化。

## 运行门禁

1. 核对高中学段、课程模块、教材版本与正文、单元位置、课时功能、学生前序作品/数据、学校设施、工具材料和地方实施要求。
2. 只有题名或目录时，不猜教材案例、尺寸、材料参数、技术规范、学生基础和既有原型；先列缺口。其他学段或中职/高职专业课不得套用本 Skill，应转“其他 / 专业课”。
3. 加工、用电、热源、化学品、压力件、机械运动、登高、激光/3D打印等须有教师预试、设备说明、PPE、分区、操作准入、停机隔离、废料处理和学校应急 SOP。无法核验时改为低风险模型、离线仿真或证据分析，但明确其不能证明真实制造/部署性能。
4. 技术试验必须在看结果前写明目的、对象、因素、控制、步骤、指标、阈值、重复、记录与停止条件；失败、离群、破坏和未达标必须保留，不能只展示“成功组”。
5. 必读 [主流模式](references/mainstream-models.md)、[输出模板](references/output-template.md)、[高中样例](references/excellent-example-senior.md) 和 [来源边界](references/sources-and-boundaries.md)。

## 工作流

### 1. 确定技术课型与课时位置

区分技术设计、结构/流程/系统分析、控制与调试、技术试验、技术表达、工程项目、技术文化伦理。画出单元或项目全链，注明本课输入和下一课继续验证什么，避免把完整设计周期压成45分钟表演。

### 2. 建立需求—约束—标准

需求来自可核验用户与使用情境；把口号转成可测试指标。至少覆盖功能、尺寸/接口、材料资源、安全、成本/时间、环境与可维护性中的相关约束，并区分硬约束、偏好和待核信息。不能把教师预设唯一造型冒充用户需求。

### 3. 确定核心增长

> 学生从“凭直觉选方案或照样制作”，走向“能根据需求和约束提出多个方案，用规范图样/模型表达，以预先声明的技术试验和原始数据评价方案，并在安全、成本、环境和伦理权衡中留下可解释的优化版本”。

目标2—4项，对齐需求表、草图/图样、计算或模型、试验计划、原始记录、故障树、评价矩阵、V1/V2和个人技术说明。

### 4. 选择主导模式

- 设计过程与原型迭代；
- 技术试验与性能优化；
- 结构/流程/系统分析；
- 控制系统建模与调试；
- 技术表达与交流；
- 工程项目与协同制造；
- 技术文化、伦理与生命周期决策。

按 [主流模式](references/mainstream-models.md) 执行不同证据链；制作不是所有课型的必经环节，但每种课型都须有个体初始判断、外部技术证据和实质修订。

### 5. 设计试验、调试与迭代闭环

先写测试协议和判据，再得到数据；同一比较需控制关键变量。流程/系统课用输入—处理—输出—反馈、边界与故障证据；技术表达课用他人能否无口头补充复现/检查作外部测试。形成V1→测试/质询→定位原因→只改可解释变量→V2→同条件复测；若时间不足，明确后续复测而不宣称优化已成立。

### 6. 保证个体技术实践

每人至少留下需求判断、方案或图样、一次原始测试/分析记录、修改理由和反思。小组制作须有可审计任务账和关键岗位轮换；不让固定“手巧者”包办，不用成品美观、速度或性别刻板评价技术能力。

### 7. 复核

- 真实用户、需求和约束是否可追溯；
- 概念/原理是否由技术行动和证据承载，而非术语贴标签；
- 多方案是否真正可选，评价标准是否在选优前确定；
- 图样、模型、仿真与实物各自能证明什么是否清楚；
- 原始失败、异常、破坏性测试和未复测项是否保留；
- 工具、材料、能源、数据、知识产权和应急是否合规；
- 是否权衡安全、成本、环境、可达性、维护和社会影响，不把创新等同炫技。

## 输出要求

严格使用 [输出模板](references/output-template.md) 十三部分，Markdown 输出。教材、参数、标准、设施安全或前序作品不足时停止完整生成，只输出证据清单、可安全先做的分析和待核方案；样例只作结构参照。
