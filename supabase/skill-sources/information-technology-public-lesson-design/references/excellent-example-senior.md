# 高中信息技术优秀教案参考样例

> 依据普通高中信息技术“数据与计算”中算法与程序实现的一般要求原创重构，不对应特定教材或编程语言。正式实施须补当前教材正文、语法/API和运行环境；样例以伪代码和经核启动程序示范正确性、效率、公平测试与调试证据。

## 一、课程基本信息

| 字段 | 内容 |

| 课题 | 名单越长，怎么找得更快——顺序查找与二分查找 |

| 主导模式 | 算法与程序验证 |
| 真实问题 | 在有序校本图书编号表中查找目标编号，选择正确且适合数据条件的算法 |

## 二、单元逻辑与教材定位

学生应已理解变量、条件/循环和列表基本表示。本课从“程序得到答案”推进到“算法有前置条件，正确性需多例验证，效率比较需公平口径”。后续可连接复杂度的直观认识、数据结构和程序优化；是否使用“大O”等术语依教材决定，不在样例强行前置。

## 三、信息科技内容与原理分析

- **输入**：有序且元素唯一的合成图书编号列表、目标编号；不使用真实借阅者信息。
- **输出**：目标位置或“未找到”，以及比较次数。
- **顺序查找**：从一端逐项比较，适用于无序/有序列表；具体提前停止规则须与算法一致。
- **二分查找**：每次比较中间项并缩小区间，前提是数据按同一规则有序；边界更新必须排除已比较位置。
- **正确性**：正常、首尾、中间、不存在、空表、重复值/无序等测试；“重复值返回哪一个”取决于需求定义。
- **效率**：同一任务、同一列表、同一目标、同一计数口径比较；墙钟时间受设备/语言影响，课堂主证据为关键比较次数。

## 四、学情与数字实践起点

学生可能认为二分永远更快，忽略排序成本和有序前提；程序能运行即正确；只测试中间存在的目标；把电脑运行毫秒差当绝对效率。诊断4分钟：给8项有序表，学生手工追踪找首项/末项/不存在项并预测两算法比较次数。区间端点混乱者获得`low—mid—high`追踪框，但不直接给更新答案。

## 五、核心增长与目标—任务—证据

**核心增长**：从凭一次运行比较“快慢”，走向在明确前置条件和公平口径下，用多类测试验证算法正确性、定位实现错误并形成条件化选择。

| 目标 | 任务 | 个体证据 | 成功标准 |
|---|---|---|---|
| 表达执行 | 手工追踪两算法 | 个人追踪表 | 区间/索引和比较序列正确 |
| 验证正确 | 设计最小测试集 | 每人测试表 | 覆盖正常、边界、异常/无效 |
| 调试实现 | 运行经核启动程序 | 个人错误假设、版本差异、复测 | 以失败定位而非重写绕过 |
| 比较迁移 | 给条件化建议 | 出口CER | 同任务同口径，说明适用条件与成本 |

## 六、重难点与问题解决链

`需求定义→数据条件→算法表达→手工追踪→实现→代表性测试→失败定位→最小修改→回归复测→公平效率比较→条件化选择`。重点是测试；难点是二分边界与前置条件。不能由本节有限规模结果推出所有环境下二分总是最好。

## 七、主导模式与公开课主线

以“同一查找任务的两种算法”为主线，制造三次认知修订：一次成功→边界失败；二分更少比较→无序数据失效；程序修好→排序成本/需求变化改变选择。最终成果是测试充分、带条件的算法建议，而不是代码展示。合作只用于交换隐藏测试和代码审查，每人先独立追踪和设计测试。

## 八、技术环境、资源、安全与分工

使用学校核准离线编程环境和教师预试的语言版本；正式教案附运行命令、依赖、启动代码来源与许可。数据为显式合成编号，不含书名偏好、借阅历史或学生身份。两人轮换：一人运行、一人逐行核对预期，测试两例后交换；每人提交自己的追踪表、测试集和调试说明。设备故障时用伪代码和已核运行日志继续，不以外部日志冒充本人运行。

## 十、教学流程

### 环节1｜诊断：一次找到够不够（4分钟）

每人手工执行两算法找中间值，随后教师换成首项/不存在项。学生写“第一次成功不能证明___”。只报告答案者补比较序列和区间。

### 环节2｜界定需求与公平口径（5分钟）

全班确认输入、输出、“未找到”、比较一次如何计数及二分的有序前提。学生独立判断重复值要返回任一/第一个是否属于同一需求；需求未定义则不得宣布错误。

### 环节3｜手工追踪二分边界（7分钟）

每人完成首、尾、不存在三例之一，再两人互审low/mid/high变化。区间不缩小者标出重复包含的mid；凭感觉跳步者必须逐轮写证据。

### 环节4｜个人设计测试集（6分钟）

先个人选最少但有区分力的用例，再与同伴合并隐藏测试。若全是“目标存在于中间”，反馈为必须覆盖首/尾、不存在/空表；无序列表用于检查前置条件，不可与有序效率结果混算。

### 环节5｜运行、失败与调试（10分钟）

轮换运行启动程序，先写预期再执行，保留报错/错误输出和版本V0。学生用追踪表定位边界更新或循环条件，提出单项修改，生成V1并跑失败例。若设备/程序不可恢复，读取标“教师预实验”的原始日志继续定位，不能抄正确版覆盖。

### 环节6｜回归与效率比较（7分钟）

V1必须重跑一个已通过例和所有失败例。随后在同一n、同一目标、同一比较计数下记录两算法；学生解释为何不能只比一次墙钟毫秒。主张“二分永远快”者加入无序输入与“是否值得先排序”的条件。

### 环节7｜迁移决策与出口（6分钟）

情境A：一次性查找小型无序清单；B：长期反复查找、可维护有序索引；C：需返回所有重复项。每人选算法并写CER：`在___数据/需求下选___；T__证明___；它不适用于___；若条件变化为___，我会___。`保存文件后登出、清除临时数据。

**总时间：4+5+7+6+10+7+6=45分钟。**

## 十一、板书与数字成果设计

```text
怎样证明“找得对、找得快”？
需求 + 数据条件 → 算法 → 实现
正确性：正常 / 首尾 / 不存在 / 空表 / 前置条件
V0失败 → 追踪定位 → 单项修改V1 → 回归测试
效率：同任务 + 同输入 + 同规模 + 同计数口径
二分：有序前提；更少比较 ≠ 所有情境总成本最低
```

## 十二、评价量规、差异化与作业

| 维度 | 3级 | 2级 | 1级 |
|---|---|---|---|
| 算法追踪 | 区间、比较序列和终止条件准确 | 主过程正确 | 只给结果或区间不收缩 |
| 测试 | 覆盖正常边界异常及前置条件 | 多例但覆盖不全 | 单一成功例 |
| 调试 | 失败定位、单项修改、回归完整 | 能修正但证据弱 | 抄正确代码/删失败 |
| 比较解释 | 公平口径并考虑前提和总成本 | 能比较次数 | 用一次毫秒值或绝对化结论 |

编程起点弱者用伪代码/追踪表定位后由同伴代输入，目标不降低；进阶者可设计返回第一个重复项并补测试。视觉困难者用高对比文本表和屏幕阅读，色觉不作为版本唯一区分。作业：为一个新列表规模设计最小测试集，解释为何每例不可被替代；可选实现，纸笔等价，20分钟。

## 十三、教学反思与核验清单

- 收集个人追踪表、测试设计、V0/V1差异、回归日志和出口CER。
- 风险：语法调试吞噬算法思考、效率口径混乱、强者代做；用经核启动程序、统一比较次数、设备轮换和个人证据纠偏。
- 核验教材算法表述、索引约定、整数除法、语言语法/版本、启动代码许可、测试预期、合成数据和删除规则。
- 下一课把查找思想迁移到更大数据或不同数据结构，并区分预处理成本、查询成本和维护成本。
