# 信息科技公开课完整输出模板

## 一、课程基本信息

学段/年级、课程名称、教材版本、册次/模块、单元、课题、课时、课型时长、主导模式、真实问题、教材证据状态、技术环境、待核项。

## 二、单元逻辑与教材定位

写课程模块、前后概念/技能、单元大概念、本课独特功能；逐项引用教材正文、任务页、数据、代码/资源。仅有课题名时停止完整生成。

## 三、信息科技内容与原理分析

列需求/用户/场景、数据/输入、处理规则/算法、输出、系统边界、底层原理、操作技能、工具依赖、技术版本、迁移范围。区分数据事实、算法、程序实现、运行结果、模拟和真实系统。

## 四、学情与数字实践起点

分析生活经验、概念、问题分解、算法/数据/系统表达、工具技能、测试调试、信息责任、设备和无障碍差异。列至少2个典型误解；设计2—4分钟个体诊断及对应分支。

## 五、核心增长与目标—任务—证据

写一句核心增长；2—4项目标逐项对应核心任务、个体学习证据、成功标准和采集时点。目标使用“界定、分解、表达、实现、测试、调试、比较、解释、评估、迁移”等可观察动词。

## 六、重难点与问题解决链

给出：`真实问题→需求/约束→分解/抽象→数据/算法/系统表达→实现或模拟→正常/边界/异常测试→调试迭代→解释原理→责任与迁移`。注明不推出的结论。

## 七、主导模式与公开课主线

说明模式选择理由、核心挑战、最终成果、产出依赖、协作必要性、教师讲解/预制边界、展示亮点为何体现学习增长；删除只为炫技的环节。

## 八、技术环境、资源、安全与分工

### 8.1 技术核准卡

| 类别 | 必填内容 |
|---|---|
| 设备/网络 | 数量、系统/浏览器、版本、网络需求、充电、投屏、外设、沙盒/离线预案 |
| 软件/平台 | 名称版本、账号方式、许可/开源协议、未成年人条款、可访问性、数据落点 |
| 数据/素材 | 来源、字段、授权、匿名/合成状态、最小化、留存/删除、偏差与用途边界 |
| 程序/模型 | 运行环境、依赖、教师预制/AI生成/学生原创标识、可解释边界 |
| 安全 | 口令/密钥不展示，最小权限，登出清理，下载/分享限制，故障停止条件 |

### 8.2 全员分工

写设备轮换矩阵，保证每人完成关键输入、预测、运行、记录、调试和解释；合作产品之外必须有个体证据。

## 九、原始工具、测试集与评价材料

按课型提供空白问题分解表、数据字典与原始/清洗记录、算法追踪表、系统框图、测试用例表、错误/故障日志、版本差异表、AI评测表、版权/风险卡。不得预填完美结果。

测试表至少包含：`编号｜输入/前置条件｜类型（正常/边界/异常/无效）｜预期｜实际｜通过否｜错误位置/假设｜修改｜复测`。算法效率比较另写输入规模、重复次数、计量方法和设备环境。

## 十、教学流程

总时长必须闭合。每环写：

| 字段 | 要求 |
|---|---|
| 环节功能/目标 | 该环推动哪项增长 |
| 场景与问题 | 真实用户、需求和约束 |
| 原理/材料 | 教材页、数据/代码/系统/模型编号 |
| 个体先行 | 每人先预测、分解、追踪、判断或设计什么 |
| 合作必要性 | 信息差、设备轮换、互测或角色互依，不泛称讨论 |
| 教师行为 | 关键话语、示范边界、巡视点、不可代做项 |
| 学生实践 | 输入、处理、输出、测试、调试、解释的可见动作 |
| 技术与安全 | 账号、权限、隐私、设备、故障与离线路径 |
| 产出 | 个体/小组文件、表、图、代码、日志或解释 |
| 典型错误 | 至少2类概念/算法/数据/系统/责任问题 |
| 反馈分支 | 针对证据的“若—则”，含设备/运行失败分支 |
| 原理落点 | 信息意识、计算思维、数字化学习创新、信息社会责任 |
| 边界 | 能说明什么、不能说明什么 |
| 过渡/时间 | 用前一产出启动下一环，分钟数可核算 |

公开课流程必须出现初版→多类测试/互测→保留失败→调试→复测→解释/迁移，不能只展示成功作品。

## 十一、板书与数字成果设计

板书动态呈现真实问题、输入—处理—输出、数据/算法/系统模型、测试证据、错误与版本修改、适用条件和责任边界。说明屏幕、实体板书、学生文件如何互补；关键结构不能只在动画里一闪而过。

## 十二、评价量规、差异化与作业

至少四维3级量规：问题界定/分解、原理表达、实现/作品、测试调试、解释迁移、数据/安全/伦理、协作与个体贡献。差异化覆盖设备熟练度、键鼠/视觉/色觉、阅读、语言表达、编程基础，提供目标等价路径。作业优先离线/低数据，写预计时长、提交证据、隐私版权和无设备替代方案。

## 十三、教学反思与核验清单

收集至少3类个体证据和版本痕迹；记录3个风险、发生信号、响应和下次修改。复核教材事实、语法/API/平台版本、数据来源、AI/模型说明、软件许可、素材版权、账号隐私、安全清理和离线预案。说明下一课如何迁移。

## 硬约束

- 不写“教师演示—学生模仿—作品展示”的纯按钮课。
- 不把能运行、界面漂亮或AI回答流畅当成正确性、可靠性或学习证据。
- 不预填所有测试通过；失败、错误和调试必须可保留。
- 不采集真实敏感数据，不公开账号、口令、密钥、定位或可识别学生信息。
- 不把模拟、平台黑箱、AI输出或教师预制代码冒充学生发现与原创。
- 不因设备少而让固定学生长期操作；全员须有目标等价证据。
